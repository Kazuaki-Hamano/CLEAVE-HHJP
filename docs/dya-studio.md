# DYA Studioでの設定

CLEAVE HHJPの現行ファームウェアは、[DYA Studio](https://studio.dya.cormoran.works/)のキー配置・マクロ・コンボ・接続管理・設定・診断に対応しています。2026年10月20日にRuntime Macroの割り当てと実行をユーザーが確認しました。

確認済みのUF2はソース `9b4ba539`、埋込ビルドIDは左右とも `e377a35a`。保存先は `output/firmware/9b4ba539/` です。左右それぞれに対応するUF2を書き込みます。通常の更新で `settings_reset` は使いません。

## 接続

- USB：左側を接続し、DYAの「USBで接続」から選びます。
- Bluetooth：PCにキーボードとして接続した状態でFn＋\|を押し、DYAの「Bluetoothで接続」から選びます。Fn＋\|は検出用の広告を60秒間有効にします。60秒経過で既存の通信を切断する処理ではありません。
- DYAで切断した後に再接続が進まない場合は、DYAのタブを閉じて開き直します。この運用で接続できることを確認済みです。ブラウザ側の再接続処理についての追加調査は終了しています。
- 保存済みキーマップは初期配置より優先されます。Fn＋\|が別の動作になっている場合は、USB接続でFnレイヤーの `\|`（0x70031）に `Studio BLE Discovery` を割り当てます。

右側は左側へ接続する子機です。DYAを右側へ直接接続する構成ではありません。

## キーマップ・マクロ・コンボ

キー配置、レイヤー名・順序、マクロ、コンボをDYAから編集できます。標準配置は `default_layer` と `fn_layer`。追加用に4つの無効なレイヤー枠を用意しています。右側1～4段目の表示位置は実物に合わせた段ずれになっています。

マクロの作成・保存と、キーへの割り当ては別の操作です。

1. マクロ画面でマクロを作成し、内容を保存します。
2. キーマップ画面でキーを選び、`Runtime Macro` を選択します。
3. 作成済みのマクロ／スロットを指定し、キー配置を保存します。
4. キーを押して実行を確認します。

ファームウェアでは `<behaviors/runtime_macro.dtsi>` を読み込み、`&rmacro <slot>` の1引数動作を公開しています。マクロ名を直接キーに保存するのではなく、割り当てられたスロット番号を使います。マクロを削除・作り直した場合は、キーの割り当ても確認してください。

## トラックパッド

「設定」の詳細設定で調整します。「トラックボール」のPMW3610設定はCirque TM040040用ではありません。

| グループ／項目 | 用途 | 初期値 |
|---|---|---|
| `cleave_left_scroll.scroll_percent` | 左パッドの縦横スクロール量 | 100 |
| `cleave_right_trackpad.speed_percent` | 右カーソルの基本速度 | 200 |
| `cleave_right_trackpad.acceleration_percent` | 指を速く動かしたときの加速の強さ。0で無効 | 0 |
| `cleave_right_trackpad.max_gain_percent` | 加速による倍率の上限。基本速度とは別 | 300 |
| `cleave_right_trackpad.native_scroll_percent` | 右端の内蔵スクロール量 | 100 |

100が1倍です。加速の強さは倍率の増え方、最大倍率はその上限を設定します。加速0では上限の変更は効きません。変更は動作に反映されますが、再起動後にも残すには各グループの「保存」が必要です。

設定は左側で一括管理し、左スクロールと右カーソルの計算状態は独立しています。Windowsアプリの旧トラックパッド設定用HID Feature 7は廃止しました。バッテリー表示・診断・更新用のFeature 1～6は維持しています。

Bluetooth保存時の `WritableStream is locked` は調査時に発生しましたが、その後ユーザーが公式サイトで設定更新できることを確認しました。試験用Webクライアントは公式サイトへ反映していないため、改善をその修正の効果とは断定していません。通常は公式サイトを使います。

## 接続先・OSとレイヤー

Bluetoothプロファイル、USB／BLEの出力優先、OS検出、接続先・OS別の既定レイヤーに対応しています。自動切替の対応先は初期状態では未設定です。Fnのような一時レイヤーを既定レイヤーにする運用は避け、追加した通常レイヤーを指定します。レイヤーの並べ替え後は対応先を確認してください。

左右の接続状態取得はBLE管理モジュールの実際のsplit接続情報に対応しています。表示位置・利用できる操作はDYAのバージョンに依存します。

## スリープ・同期

左右とも初期のディープスリープは30分です。DYAで待機時間を変更できます。復帰は各側のキーで行い、パッドへの接触は復帰条件にしていません。左右のキー復帰は確認済みです。

待機時間の変更は左右共通です。左側が保存して右側へ送り、右側の保存完了応答まで未完了データを保持します。右側が切断中だった場合は再接続後に再送します。トラックパッドの設定は左側で処理するため、この同期とは別です。

## 診断と確認範囲

- デバイス情報：接続している左側のビルド・稼働時間・リセット情報など。
- キースキャン：左右の入力統計を左側へ集約。
- ウォッチドッグ：左右の停止・異常記録。ソフトウェア検出は30秒、起動時の猶予は30秒。故意の停止を起こす試験機能は無効。
- スタック使用量：左側の使用量を確認。キー注入・ログ捕捉などの開発操作は無効。

通常動作と診断画面はユーザー確認済みです。故意のフリーズ・クラッシュ試験や消費電流の測定を実施済みとはしていません。

## 実装・検証

依存リビジョンは [`config/west.yml`](../config/west.yml) に固定しています。左右で読み込む設定は各 `cleave_hhjp_left.conf`／`cleave_hhjp_right.conf`。BLE管理・設定RPC・既定レイヤーの補正は `modules/`、Cirqueドライバーは `src/pinnacle/`、トラックパッド設定は `src/trackpad_settings.c` にあります。

`src/studio/` は固定ZMKのGATTトランスポートを限定的に置き換え、送信サイズをATT MTU−3以内に収め、送信待ち時の接続参照を解放します。USBや右側のStudioトランスポートは変更しません。これはブラウザの同じタブ内での再接続を保証する変更ではありません。出典は同ディレクトリの `UPSTREAM.md` に記録しています。

確認済みのビルドは [Actions Run 39358929004](https://github.com/Kazuaki-Hamano/CLEAVE-HHJP/actions/runs/39358929004)。UF2整合性、左右の実効設定、Runtime MacroのDTS定義と左側メタデータ、既存キーマップを検証済みです。実機でRuntime Macroの正常動作が確認されたため、DYA対応の区切りとします。

開発時は `tools/dya-studio/verify_build.py` と各回帰テストを使います。個々の導入試験記録はGit履歴に残し、現在の利用方法はこのページを参照します。
