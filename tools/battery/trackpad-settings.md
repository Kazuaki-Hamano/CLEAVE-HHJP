# タッチパッド設定

対応ファームウェアと、`output/battery/dist/CLEAVE-Battery.exe`を使用します。初回は左右両方を更新します。最新版は`502000da`です。左右パッド対応済みの構成からの更新は左UF2のみで利用でき、右UF2とアプリの更新は不要です。成果物とビルドIDは[生成物の保存場所](../../docs/generated-output.md)を参照してください。
左側をUSB接続し、トレイアイコンを右クリックして「タッチパッド設定」を開きます。
右側は通常どおり電源を入れ、左右を接続してください。

左パッドは通常時に縦横スクロール、Fn中は左スワイプで戻る・右スワイプで進むとして使います。右はFn中もカーソル移動です。アプリの速度と加速は右カーソル、スクロール量は左の縦横スクロールに適用します。左右の端数は独立し、検出感度は両側とも1x固定です。右端スクロール倍率の追加に合わせ、左UF2とアプリの更新が必要です。右側は内蔵スクロール対応版をそのまま使えます。

スワイプは横の累積移動64カウント以上かつ縦の2倍以上で1回発動し、約180ms動きが止まると再受付します。Fnの押し直しで判定をリセットします。OSにはConsumerのAC Back / AC Forwardを送り、対応するブラウザーやアプリで動作します。左スワイプ中はカーソル移動・スクロールを出しません。タップクリックは従来どおりです。

| 項目 | 範囲 | 初期値 | 意味 |
|---|---|---|---|
| 基本速度 | 0.3～8.0倍、0.1倍刻み | 2倍 | 加速前の移動倍率 |
| 加速の強さ | 0～300% | 0% | 指の速さに対する追加倍率。0で加速なし |
| 加速の最大倍率 | 1.0～8.0倍、0.1倍刻み | 3倍 | 加速部分の上限。基本速度には別に掛かる |
| 左パッドスクロール量 | 0.1～4.0倍、0.1倍刻み | 1.0倍 | 左の縦横スクロールに対する倍率 |
| 右端スクロール量 | 0.1～4.0倍、0.1倍刻み | 1.0倍 | 右パッドのチップ内蔵スクロールに対する倍率 |

変更は約0.2秒の待ち時間の後に左側へ反映されます。検出感度は1x固定です。旧保存設定は速度・加速を引き継ぎ、倍率は最も近い0.1倍刻みに丸めます。左スクロール量はversion 2以降の保存値を引き継ぎます。右端スクロール量は1.0倍で開始し、感度は旧保存値によらず1xへ戻します。

「反映済み」を確認し、「キーボードに保存」を押すと左側の不揮発設定へ保存します。調整中はフラッシュへ書き込みません。未保存の変更は左側の再起動で失われます。右側の感度1xも起動・再接続後に確認します。保存成功は書き込み処理完了後に表示し、センサーが未反映・未接続なら保存ボタンを無効にします。

USBで設定した値は、PCとのBluetooth接続でもカーソル処理に使われます。ただし設定アプリからの変更は左側USB接続が必要です。Windowsのマウス速度は変更しません。

Fn（LANG2・旧LANG1位置の長押し、左右の専用Fn）中は、右パッドがカーソル移動、左パッドが左右スワイプによる戻る／進むです。左の通常時スクロールにはカーソル速度と加速を適用せず、縦は`-Y × スクロール倍率 / 16`、横は`X × スクロール倍率 / 16`でホイール値へ変換し、端数を保持します。タップの左右クリックは維持します。Mouseレイヤーは削除され、旧LANG1位置は短押しINT4・200ms長押しFnです。

## 実装と通信

右パッドのチップ内蔵スクロールは右端を上下になぞる操作で実機確認済み・正式採用です。「右端スクロール量」で独立して調整します。1.0倍が従来と同じ量です。基本速度と加速は掛けません。左のスクロール量とは別の端数を保持し、低倍率でも小さい入力を蓄積します。倍率変更時には残っていた端数をリセットします。倍率の反映・保存・再起動後の保持は、この版の書き込み後に実機確認してください。

左側のUSB vendor HID Feature Report 7（ID込み32バイト）を使用します。既存レポート1～6と最大バッファ長は維持します。

- SET: `[7, 3, command, 0, speed_u16, acceleration_u16, maximum_u16, sensitivity_u8, zero...]`。整数はlittle-endian、倍率は百分率。commandは0=RAM反映、1=反映して保存。感度byte10は1固定、左スクロール倍率はbyte28～29、右端スクロール倍率はbyte30～31のLE16です。他の予約領域は0。
- GET: `[7, 3, flags, 0, speed_u16, acceleration_u16, maximum_u16, desired_u8, applied_u8, sensor_error_i8, save_error_i8, generation_u16, diagnostics...]`。左スクロール倍率はbyte28～29、右端スクロール倍率はbyte30～31。旧アプリとの混在を防ぐためHID version=3です。
- flags: bit0=保存値との差分あり、bit1=右側の感度反映確認済み、bit2=保存処理中。右側の結果は最終取得から5秒で失効します。
- 設定保存キー: `cleave_trackpad/config`。バージョン2と9バイトの設定値を保存。旧版のバージョン1＋7バイトも移行して読み込みます。
- 左右間の感度指定: ZMK標準のbehavior転送で右側の`tp_sens`へ固定値1を約1秒間隔で送ります。右側はセンサー変更処理後、標準input-split 0のMSCイベント（code=`0xc1e0`、上位16bit=`0x5450`、次の8bit=符号付きエラー、下位8bit=適用感度）で結果を返します。このイベントは軸・ボタン操作ではなく、syncも付けません。Fn中でも結果を確認できます。
- 旧GATTサービス`b6f4a630-3790-4c3c-934d-911d84233b10`と値`b6f4a631-3790-4c3c-934d-911d84233b10`は互換用に残していますが、感度の定期取得には使いません。

診断情報はbyte16が1の場合に有効です。byte17=通信段階、18=暗号化レベル（旧方式のみ）、19=ATTエラー（旧方式のみ）、20～21=送信APIの戻り値（符号付きLE16）、22=応答長、24～25=試行回数、26～27=応答回数です。通信段階は0=未接続、3=送信エラー、8=標準split転送後の応答待ち、9=標準splitで結果受信済みです。旧方式の1～7もアプリで読み取れます。byte16が0の旧版でも基本設定の形式は同じです。

GATTのバッファ確保は待機する可能性があるため、充電状態・更新情報の定期取得は専用の`cleave_peer_work_q`で実行します。感度指定はGATT読み取りを直接行わず、ZMKの標準送信キューへ渡します。

速度は各パケットのX/Yからユークリッド距離を整数で計算し、経過時間で「10ms当たりの移動量」に正規化します。直近速度を平滑化し、次のパケットの両軸に同じ倍率を適用します。加速倍率（百分率）は`min(最大倍率, 100 + 加速の強さ × 速度 / 10)`。最終倍率は基本速度との積です。150ms以上入力が途切れたら加速履歴をリセットし、小数の移動量は端数を蓄積します。

センサードライバーは`src/pinnacle/`に固定版から取り込みました。出典と変更点は[UPSTREAM.md](../../src/pinnacle/UPSTREAM.md)を参照してください。感度変更とパケット取得は同じwork queueで直列化し、再調整のポーリングにはタイムアウトを設けています。

設定反映・保存・再起動後の保持はユーザー確認済みです。現行のスクロール倍率は計算テストと設定画面の送信テストを実施済みです。使い心地に合わせて調整してください。

Fn＋Qは左クリック、Fn＋Eは右クリックです。キーを押している間はボタンを保持し、離すと解放します。FnとQを押したまま右パッドで移動し、Qを離すとドロップできます。最初の確認には専用Fnキーを使用し、LANG2・旧LANG1長押しの場合は200ms待ってからクリックキーを押します。
